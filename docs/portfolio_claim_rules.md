# Portfolio Claim Rules

## Unsafe claims
“This repo is enterprise-ready.” “The system is secure.” “All risks are covered.” “The project is compliant/certified.”

## Safer claims
“This repository has a local readiness scan that identified architecture indicators, patch points, gaps, evidence, and safe next tasks.”

## Evidence required to upgrade claims
Implementation evidence, negative tests, demo attacks, CI logs, staging validation, telemetry/audit evidence, and external validation.

## Public-safe wording
Use conservative wording that states what was scanned and what evidence exists without claiming final effectiveness.

## Internal-only wording
Detailed paths, internal architecture notes, secret indicators, and exploit details should remain internal.

## Claims never allowed without external validation
Compliance, certification, complete security, and enterprise production-candidate readiness require external validation.
